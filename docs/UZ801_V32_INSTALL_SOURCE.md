# UZ801 V3.2 installation source

The installation reference is the first-hand account covering two UZ801 V3.2
boards: https://ryjelsum.me/homelab/uz801-v3.2-postmarketos/ (2025-08-30,
with a 2026 addendum). The linked device wiki is also relevant:
https://wiki.postmarketos.org/wiki/Zhihe_series_LTE_dongles_(generic-zhihe).

Use the documented qcom-msm8916/extlinux console installation generated by
official pmbootstrap. The combined boot/root image goes into the existing
userdata partition. Keep the original device GPT and modem/NV partitions.
This replaces the earlier experimental Debian installation plan.

The optional GitHub Actions workflow builds the normal postmarketOS v26.06
image on Linux. It pins pmbootstrap and pmaports, includes Nginx and standard
network/SSH tools, and checks that the image fits this unit's 2632384000-byte
userdata partition. It contains no USB flash commands or custom image encoder.
Build success is not hardware compatibility or boot success.

No Wi-Fi credentials, Cloudflare credentials, private SSH keys, device
identifiers, original firmware or backup files are used by the workflow.
The upstream `install --password` automation flag uses the **public dummy
password `123456`** for user `user`. Replace/disable this login locally before
connecting the installed system to an external network. No Wi-Fi profile is
included in the image.

The documented bootchain uses lk1st, qhypstub and Linaro Android-88 SBL1/TZ.
An archived vendor download is linked from the device wiki:
https://web.archive.org/web/20241225090617/https://releases.linaro.org/96boards/dragonboard410c/linaro/rescue/17.09/dragonboard410c_bootloader_emmc_android-88.zip.
Local comparison found its SBL1/TZ identical to the first-hand guide's archive.
This is provenance evidence, not a successful boot test of this USB unit.

Do not reuse a newer, oversized TZ by merging partitions. Follow the guide's
bootloader verification and firmware sequence. Keep hardware outcomes distinct
from checksums, image generation and fastboot command return codes.

## Windows USB driver selection

Only change the driver of the connected dongle's matching device. The
observed Linux USB VID/PID is `18d1:d001`; the CDC NCM function is interface 00.

1. If the composite parent appears as Android ADB Recovery Interface under
   LeMobile Android Device, select Update driver, Browse my computer, then
   Let me pick. Select Microsoft's USB Composite Device. If necessary,
   select Have Disk and the existing `C:\Windows\INF\usb.inf`.
2. If CDC NCM appears under Other devices, use the same wizard, choose
   Network adapters, Microsoft, UsbNcm Host Device. Alternatively use Have
   Disk with the existing `C:\Windows\INF\usbncm.inf`.
3. Verify the new network adapter and its USB subnet before attempting SSH.
   Do not replace the CDC NCM function with an Android or RNDIS driver.

Microsoft documents NCM host support on Windows 10 build 18362 and later,
and the device name UsbNcm Host Device:
https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/factoryos/connect-using-usb-ncm.
This host is build 19045 and already contains the matching driver package.

The USB/firmware operation logs, backup, identifiers and credentials remain
local under ignored directories. They are not part of this repository.
